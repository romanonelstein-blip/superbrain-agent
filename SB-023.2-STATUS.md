# SB-023.2 — Windows startup and visibility hardening

This patch targets the exact failure mode where the user launches a new ZIP but still sees an older Mission Control or cannot tell why Quick answer / Research is unavailable.

Changes:
- the Windows launcher stops only stale `nexus1000.sb022_server` processes before starting;
- every start uses a fresh OS-assigned loopback port;
- the browser URL contains a fresh build token and is written to `work/mission-control-url.txt`;
- first start creates `.env` from `.env.example` if it does not exist;
- `configure-superbrain.bat` opens the correct local `.env` file;
- `superbrain-doctor.bat` reports Python, Node.js, bridge presence and runs focused health tests;
- Mission Control visibly identifies itself as `SB-023.2 · FIXED · INTERACTIVE`;
- runtime status now exposes safe diagnostics without showing secret values;
- model-provider calls fail with an explicit Node.js requirement when Node is missing;
- static assets continue to use `no-store` plus cache-busted asset URLs.

NexusOrchestrator remains the only final-decision runtime. No automatic change application was introduced.
